### Git LFS recommendation

- Total `assets/` is 418 MB; the largest single file is 63.3 MB (`pokemon-like-3d-model.glb`),
  under GitHub's 100 MB hard limit but above the 50 MB warning. Every other file is < 20 MB
  (largest MP3 ~10 MB). Nothing *must* go through LFS for the limit.
- GitHub's soft repository size guidance is ~1 GB; with `course-materials` (already ~100 MB
  tracked) plus 418 MB of assets the repo would sit around 550 MB on the first push and grow
  on every regeneration (every `generate_*` run rewrites all GLBs and PNG renders, so a
  regeneration commit adds ~50–200 MB of history).
- **Recommendation:** use Git LFS for `assets/**/*.{glb,png,mp3,ogg,wav,mp4}` and
  `course-materials/*.zip`, keep manifests, ledgers, catalogues and READMEs as plain files.
  Track patterns via `.gitattributes` before the first `git add assets/`. If the team wants to
  avoid LFS quota costs: exclude `assets/audio/music/` (152 MB, audition-only, downloadable
  again from the catalogue URLs), `_input_snapshot/`, `renders/`, and the 60 MB Tripo panel;
  the remaining plain-file footprint is ~120 MB of GLBs plus ~50 MB of PNG sheets and voice
  WAVs, which is tolerable as plain git for a small team but will still churn on every regen.
  LFS is the safer default.
